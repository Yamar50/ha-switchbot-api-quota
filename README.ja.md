# SwitchBot API残り回数

[English](README.md)

SwitchBot OpenAPIの応答ヘッダー `X-RateLimit-Remaining` を1時間ごとに取得し、
残り回数と「残数が増えたことを観測した時刻」をHome Assistantに表示する非公式統合です。
既存の **SwitchBot Cloud** 登録の認証を利用するので、トークンやシークレットの再入力は不要です。
デバイス操作やSwitchBot Cloudのポーリング設定は変更しません。

## インストール

Home Assistant **2026.11.0以降**と、設定済みのSwitchBot Cloud登録が必要です。
SwitchBot Bluetoothだけでは利用できません。

1. HACS（またはマーケットプレイス）の「カスタムリポジトリ」を開きます。
2. `https://github.com/Yamar50/ha-switchbot-api-quota` を追加し、種類に「統合」を選びます。
3. **SwitchBot API Quota** をダウンロードし、HAを再起動します。
4. **設定 → デバイスとサービス → 統合を追加 → SwitchBot API残り回数** を開きます。
5. 使用するSwitchBot Cloudの登録を選択して送信します。

これはカスタムリポジトリでの導入手順です。GitHub公開とHACS標準一覧への採用は別です。
手動導入の場合は `custom_components/switchbot_quota` をHAの同名フォルダへコピーします。

既存の手動導入版から更新する場合は、バックアップ後にコードだけを置き換えてください。
統合の登録は削除・再作成せず維持します。ドメイン、固有ID、既定のエンティティID、保存形式は維持しています。
削除すると保存済みの取得予定時刻・観測区間が失われます。

## 表示と履歴

| 既定のエンティティID | 内容 |
| --- | --- |
| `sensor.switchbot_api_remaining` | サーバーが返した残り回数 |
| `sensor.switchbot_api_last_increase` | 前回より大きい残数を初めて観測した時刻 |

実際のIDは改名や複数登録によって異なる場合があります。表示名は日本語・英語に対応します。
残数センサーを開くと履歴を確認できます。`state_class: measurement` があるため、
Recorderの対象であれば長期統計も利用できます。履歴の保存期間や除外設定は変更しません。

増加時刻センサーは、最初の増加を観測するまでは「不明」です。属性には次を記録します。

- `increase_window_start`：直前に成功した取得時刻。
- `last_increase_observed_at`：残数の増加を観測した時刻。
- `remaining_before_increase` / `remaining_after_increase`：比較した残数。
- `increases_observed`：観測した増加の回数。

この2つの時刻の間に残数が補充されたと判断できます。通常は約1時間の幅ですが、
通信失敗・HA停止があると広がります。取得の間にリセットと大量消費が起きて次の値が前回以下なら、
リセットを検出できません。正確なリセット時刻や、HAだけのAPI消費回数を示すものではありません。

## API消費と取得失敗

- 初回登録時に1回、以降は毎時 `GET /v1.1/devices` を1回呼びます。
  **監視するCloud登録1つにつき、通常1日約24回の追加消費**です。監視そのものもAPI枠を消費します。
- 試行時刻を通信前に保存するため、再読込・HA再起動・手動更新をしても1時間以内は再取得しません。
- 失敗時の即時リトライはせず、次の1時間後に再試行します。
- 通信失敗・認証拒否・ヘッダー欠落などは残数を `unavailable` にします。0で代用しません。
  前回成功値は内部に保持して次の比較に使います。
- HTTP 429でも有効な残数ヘッダーがあれば採用し、実際の残数が0なら0と表示します。
- 過去に観測した増加時刻は、今回の取得が失敗しても保持します。
- リダイレクトには追従しません。機器一覧の本文は解析・保存・ログ出力せず、
  認証情報もこの統合の設定や保存ファイルへ複製しません。

残数センサーの属性 `observed_at`、`last_attempt_at`、`next_attempt_at` で、成功時刻・試行時刻・次回予定を確認できます。
`http_status`、`server_date`、認証情報を含まない `last_error` も確認できます。

このヘッダーは実機と[利用者の報告](https://github.com/OpenWonderLabs/SwitchBotAPI/issues/518)で観測されたものですが、
[公開API仕様](https://github.com/OpenWonderLabs/SwitchBotAPI)に保証された項目ではありません。
将来変更・削除される可能性があり、固定のリセット時刻や上限回数は仮定していません。

## 保守・削除

認証の更新は元のSwitchBot Cloud登録で行います。この統合は取得のたびに最新の認証情報を参照します。
元の登録が削除された場合は取得不能になります。別のCloud登録に変更した場合は、その登録を選び直して新たに監視します。

監視停止は、この統合の登録を「無効」にします。撤去する場合はこの統合の登録を削除し、
コードフォルダを削除してHAを再起動します。引き続き使うSwitchBot Cloudの登録は残してください。
統合の削除では観測用の保存状態を消しますが、Recorder履歴を直接削除することはありません。

## 検証環境

元の実装は2026-11-11にSwitchBot AI Hub上の **Home Assistant Core 2026.11.0** で、
実際の残数取得・Recorder履歴・保存・再読込と手動更新の取得抑制を確認しました。
2026-11-13には継続中の毎時取得と実際の残数増加の記録も読み取りで確認しました。
公開用の18テストはHA 2026.11.0／Python 3.14.10で全件合格しています。
テストは実際のHAライブラリと模擬HTTP・保存・時計を使い、SwitchBot APIを消費せず実施します。
取得と観測のロジックは稼働版と同じです。すべての環境や将来のAPI動作を保証するものではありません。

テストの実行方法と詳細は[英語README](README.md#validation-and-development)を参照してください。
